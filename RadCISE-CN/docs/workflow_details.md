# RadCISE-CN 流程说明

## 1. Direct-SRU 拆解

输入一段中文影像报告“所见”，输出 SRU。SRU 是可以独立判断是否报告正确的临床语义单元。RadCISE-CN 采用 direct-SRU，不再先拆 atomic finding。

关键原则：

- 以病灶/病变过程为中心，而不是以句子为中心。
- 一个病灶的大小、位置、边界、密度、强化、内部成分、邻近改变通常作为属性，不单独拆分。
- 淋巴结、血管受累、胸膜/腹膜受累、积液、梗阻、气胸、骨折、出血等若具有独立临床意义，可拆成独立 SRU。
- 普通正常/阴性描述可以合并；检查核心相关关键阴性应保留。

## 2. Joint concept / tier / match

Reference SRU 和 Generated SRU 被放在同一个 prompt 中，建立共享 concept map。分层不是分别对两份报告独立做，而是基于全病例语境生成一套共用的 A1/A2/A3/N。

每个 concept 包含：

- tier: A1/A2/A3/N
- concept_axis: 主病灶、局部效应、淋巴结、胸膜/腹膜/浆膜、积液/梗阻/血管/并发症、偶发异常、正常阴性、技术质量等
- concept_type: matched / reference_only / generated_only
- match_quality: full / substantial / attribute_conflict / limited / core_conflict / none

## 3. 中文医学术语处理

RadCISE-CN 特别加入中文术语边界：

- “未见肺结节/无胸腔积液/未见充盈缺损”是阴性，不因含“结节/积液/充盈缺损”而当作阳性。
- “见/可见/显示/提示/考虑/伴/形成/呈/增厚/增大/强化/狭窄/扩张/充盈缺损”通常提示阳性观察。
- “透亮度增强/透亮度增高”是肺透亮度改变，不代表增强 CT。
- “增强后强化/增强扫描/注入造影剂/肺动脉CTA/靶区血管三维重建”才提示增强或 CTPA 背景。
- “少许/少量/微量/轻度/点状/条索/陈旧/钙化/退变/非特异性”通常降低重要性，但不覆盖明确高危病灶本身。

## 4. 确定性 guard

代码层面保留并中文化以下泛化 guard：

- 普通阴性句不能成为 A1。
- 低风险轻微异常不能仅因“最显眼”而成为 A1。
- 小量/微量积液在无高危特征时下调为 A3。
- 父病灶的局部非决定性属性不应独立成为 A1/A2。
- 局灶轻微慢性过程和弥漫广泛急性过程不能因泛词相同而强行匹配。
- 生成报告多出的高影响主病灶应作为一个 generated_only A1，而不是拆成多个 A1。

## 5. 评分

每个 tier 内计算基于 match_quality 的加权 F1，再按动态权重聚合：

- 有 A1 时，A1 主导；A2 最高约 20%；A3+N 最高约 5%。
- 无 A1 时，A2 成为主要评分对象。
- 无 A1/A2 时，A3 成为主要评分对象。
- 只有 N 时，评估普通正常/阴性描述一致性。

因此，RadCISE-CN 奖励核心临床发现准确，弱化模板化正常句堆叠对分数的影响。
